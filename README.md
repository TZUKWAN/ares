ARES 主界面现分为 **流程编排｜项目推进**。编排继续按 **比赛 → 赛道 → 届次/组别（按需）** 整理，不需要先建项目；项目采用一套已保存流程，独立记录实际作品、分工、进度、验收和版本。详细实施与验证见 [两工作区改造](docs/TWO_WORKSPACES_20261112.md)。

1. **流程编排**：选择比赛与赛道，直接在节点画布中增删、排序、调整目标、交付物和技能。流程助手同步当前流程、选中步骤和未保存草稿；AI 建议可以查看变更、带入草稿，再保存。
2. **用于新项目**：保存流程后填写项目名称及目录，采用当前看到的准确流程版本。旧项目继续使用各自固定版本，编排草稿不会改动旧项目。
3. **项目推进**：星图对应本项目阶段，查看节点、实际作品及工作状态；右侧原生项目助手跟随步骤与作品定位，发送时绑定原生消息，排队后切换界面也不会借用后来选中的对象。
4. **金山协作**：项目作品区保留本地/金山与对照；两工作区切换只隐藏云视口，同一网页与租约保活。金山处理登录、分享与共同编辑，ARES 负责关联作品、审阅云稿采用及本地版本记录。
5. **验收与版本**：原实际文件检查、内容复核、人工验收、项目快照、运行空闲门禁与 MCP 隔离保留。流程或技能遇到并发变更会保留草稿并提示，不自动覆盖别人修改。

已有项目时默认进入项目推进；没有项目时进入流程编排。常驻助手随工作区切换正确角色，并保留两边各自输入与原生会话。赛事目录不等于所有当届规则均已核验；没有专属方案的比赛以明确的起始草稿进入编排，按真实规则完善。

客户端缓存 `2.3.0-polish1`，自包含构建为19模块/3字体/4份原始动效素材，经既有 `workshop-scene.js` 与样式入口加载。修改后运行 `node scripts/build_forge.mjs`，用 `--check` 检查产物。跨平台页面用 `node scripts/build_portable_ui.mjs`，本地插件包用 `node scripts/package_plugins.mjs --out <源码外的输出目录>`。当前用户窗口没有代操作或重载；自有验证环境的结果与在线模型/云端写入验收分开记录。

## 工作台

- **流程工作室**：12 类默认流程、98 个默认步骤。复制/编辑流程，增删/复制/拖动步骤，配置输入、依赖、执行方式、技能、三类提示词、参数和产物。
- **赛事目录**：内置 132 项赛事、168 条可选赛道映射，另保留 1 条历史兼容赛道；用户可自行增删、改名和恢复比赛及赛道。支持完整搜索、领域筛选及流程选择。通用配置覆盖不等于当届规则已核验或全部赛事实测。
- **项目空间**：关联目录、建档、继续固定版本会话、登记资料与规则、检查实际文件、内容复核和阻断。
- **技能库**：28 个真实本地能力，按需读正文、绑定步骤、创建技能和编辑本地副本。副本保存在配置，不覆盖内置文件。
- **项目版本**：与流程节点同页查看真实作品工作版本、阶段/提交快照和历史；完整原生声明诊断收进流程配置。旧项目保留版本，升级先展示差异。

UI 为全新实现，跟随 DSH 明暗主题，适配窄面板和手机。无项目也可以编排。

## 2.2日常操作

1. 在流程配置点击“引导构建流程”，填写目标，选择模板或每行写“阶段 | 交付文件名”；预览后放入草稿并保存。模板推荐与编排方法明确标注，不伪称AI生成。
2. 项目节点点击“执行本步”，会真正提交到DSH原生会话，显示运行/停止/结果。真实产物检查和工作版本形成后等待人工验收；已知执行错误会保留告警，未知结果不自动重发。
3. 金山工作稿点击“拉取文本候选”，选择对应作品查看差异，再“采用云稿并保存工作版本”。原字节保留，相关节点需重验；Word采用是文字转换的新工作稿，原版式不承诺保真。
4. 在“作品历史”或项目版本详情选择“对比”，比较当前工作稿/两版历史，查看实际新增、移除和修改。Office提取正文比较，二进制展示内容指纹，不假称版式对比。
5. “资料与规则→逐项核对规则”绑定实际证据；“导出复用/导入子插件”传固定包，导入不带执行权限；参数表单会保留类型和默认值。
6. 问卷预测试可展开多场景/种子/样本量比较，结果保留实际CSV及诊断；“安排时间与待办”设置截止、分工和预计用时，在工作台内显示逾期/阻塞提示。

## 使用

1. 选择流程，按实际目标调整步骤并保存配置。
2. 创建项目：指定真实目录、赛事、赛道、届次、组别与流程。
3. 从项目打开 ARES 会话。读取当前任务，按需加载技能，执行真实工作。
4. 检查实际产物，阅读/观看内容后登记复核；缺输入或能力时保留阻断。
5. 检查全项目，单独核验当届规则和提交要求。

自然语言入口：

1. 「我要准备数学建模训练，已有赛题和附件，先盘点资料并拆解问题。」
2. 「我已有创业材料，帮我核对证据并准备答辩，不需要另外做原型。」
3. 「我准备市场调查比赛，先设计抽样和问卷，真实数据由团队采集。」
4. 「我有一个软件工程，按命题检查实现、测试和技术报告。」
5. 「这是设计命题，帮我比较创意方案，按海报作品安排流程。」
6. 「项目事实变化了，请只复核受影响的任务和产物。」

## 状态与证据

文件存在不会直接显示已验收。结构检查实际解析文档、数据和文件；空文件、损坏文档和空目录不能通过。
任务完成需要有效产物及绑定当前 SHA256 的内容复核。产物、复核记录、输入或前置结果变化后，需要重新验收。

产物分独立文件、目录、文内章节，要求分必需、可选、条件必需。条件输入未知时保留缺口。评分建议、机器检查、内容复核和官方提交条件分别记录，未知权重不转为伪造总分。

规则基线保存原文网址、项目内快照、适用范围和可在原文找到的摘录。文件与摘录校验不能替用户认证主办方身份或所有条款。

调整已有项目流程时，先看差异再采用，变化的步骤重新验收。旧会话仍使用旧版本，应从项目重新打开执行会话。
快照固定流程、技能与资源，不冻结 DSH 程序、ARES 引擎、系统依赖、账号和项目文件。

## DSH 接入与共创

保留单个 bundle，入口 `index.js`，浏览器适配器 `client/client.js`，原生会话插件 `ares/runtime`。
原生注册采用实际桌面接口的顶层 `id/name/plugins`，不修改 METIS 或 DSH 安装包。

配置助手直接使用 DSH 原生会话、输入栏和消息区，模型选择、思考、工具调用、流式回复和停止都由 DSH 管理。对话固定为 ARES 配置编辑，不选择项目或工作区，不另写模型请求循环。

2.0.3 为编辑助手和比赛会话加载完整 DSH 标准原生工具组合，保留文件、终端、搜索、联网、技能和宿主全局扩展/MCP；不设置工具白名单。高级工具保留，默认仍由单一 Agent 工作，仅在用户明确要求时启动子 Agent、workflow 或 goal。DSH 原生权限、沙箱和连接状态继续生效。

编辑会话激活后读取真实工具目录，并在发送模型请求前比对标准预设和最终组装目录；缺失时显示具体错误。重连时只更新空闲编辑 Agent 的旧工具组合，保留同一会话、消息和提案。源码路径由 `ares_config_read kind=context` 返回，工作台配置继续通过版本化提案修改。验证依据与边界见 [原生工具修正说明](docs/NATIVE_TOOLS_2_0_3.md)。
后端自动管理编辑通道及内部会话目录；切换流程或技能仍保留同一对话。`ares_config_read` / `ares_config_edit` 读取真实草稿并产生可审阅提案，应用并保存后生效。
未加载新版原生服务时提示重载 ARES，不回退到通用欢迎页或自制聊天。手动编排仍可使用；读技能不会自动安装依赖。

当前桌面 profile 通过 Junction 引用本目录。源文件更新后，需重新加载 ARES 插件与工作台资源才会作用到运行中的 DSH；本插件不自动重启用户应用。

## 原生工具体检

顶部常驻“体检 ARES”；流程配置助手标题中常驻“重新连接”和“工具体检”。原生助手连接且空闲后可执行体检。它使用当前真实编辑会话，核对实际工具目录、当前配置服务、内部测试文件读写和固定终端计算；PTC通过原生SDK调用。Auto审批下，体检通过DSH原生消息入口使用当前选定模型生成真实工具调用，审批上下文由DSH正常回合产生；非Auto保留直接安全探针。它不新建会话或DSH，不改变MCP或权限设置。DSH仍可请求原生授权，按钮支持取消。缺少原生消息入口、会话忙碌、有待发消息或被取消时不会补造调用历史。通过条件来自真实request/header、可见工具调用、关联回执、当前配置服务标识、实际文件与终端任务；模型文字自述不能使检查通过。

报告实际保存在 `<ARES_HOME或DSH_HOME>/ares-health-reports/<id>.json`，界面返回确切路径。缺工具、旧服务、未知任务和未完成检查均不会显示通过。检查只执行上述有限安全操作；外部MCP及有副作用的能力仍按实际连接、权限与具体任务验收。
