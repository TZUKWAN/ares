# ARES 比赛要求、研究证据与作品联动

本轮在现有运行版内开发。基线为 `0aa72dfd60788c2027ca355a72d8ce8b8175dfda`，沿用项目修订、工作流、对象版本、所有者权限、原生助手、验收及 MCP 范围。PR 保持 Draft。实现和验收均使用专用项目。

| 单元 | 最小可验证目标及主要文件 | 执行与验证 | 完成标准 |
| --- | --- | --- | --- |
| K 金山账号入口 | `host/kdocs-account.js`、客户端账号页及原协作设置 | 页面可见认证入口，独立核对密钥链认证和真实目录访问。登录由用户明确点击启动，状态中不返回凭据。权限、重复请求、终止、真实 ARES 页面读取验收 | 用户在 ARES 内找到金山账号状态并选择当前项目协作目录 |
| R 比赛要求 | 要求提取、规范化条目、来源快照和流程映射 | 原文导入，助手结构化建议，人工逐项采用，条款锚点、范围和旧版变更检查 | 每项要求有原文、适用范围、步骤或作品，采用后走原规则验收 |
| E 事实与证据 | 项目事实记录、版本引用、作品影响检查 | 支持来源片段、研究版本和实际计算回执，引用到章节或幻灯片，更新产生待核对差异 | 可定位原始证据，受影响引用可见，既有作品和验收版本一致 |
| X 模型实验 | 复用后台任务的 Python/R 实验执行与对比 | 显式批准本机脚本，固定输入字节、脚本、参数及环境信息，真实进程回执、取消和重试 | 两个真实方案可比并可重跑，错误和未知执行保持真实状态 |
| C 正式回收 | 正式问卷采集连接器与样本复核 | 优先评估金山表单实际可用 API，读取平台原始答卷及来源。按定稿变量映射，保存原始稿、异常和采用决定 | 正式数据进入原答卷通路，模拟数据门禁、版本及复核可追溯 |
| D 答辩 | 固定作品与规则驱动的演练 | 当前原生助手创建有证据定位的问题和反馈，用户确认后写回待办 | 回答关联固定版本，问题可回到步骤，模拟评价标明性质 |
| T 跨赛改编 | 新项目复用选定已固定作品 | 对比目标赛事要求，显式映射复用材料，复制实际内容及来源 | 原项目不变，新项目不继承验收结论，缺口与新作品独立保存 |
| F 最终回归 | 两系统全量、规则、构建、便携包及真实金山 | 每单元先定向验证修复，再运行完整回归、截图、包校验、Git/PR 审计 | 精确 SHA 和证据可复核，所有环境限制明确记录 |

新增能力放入当前项目和当前对象操作，常驻助手继续使用 DSH 原生会话。研究工具界面使用现有深色、暖金配色和组件。外部采集只在明确授权的地址操作，凭据由原宿主或金山密钥链持有。所有自动提取和答辩建议需人工确认。自由编辑的金山段落先显示差异建议，生成稿更新保持明确版本基线。
