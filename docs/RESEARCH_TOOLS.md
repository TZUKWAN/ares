# ARES 研究工具中心

在 DSH 打开已有项目，或先创建竞赛项目，然后从项目页头进入「研究工具」。工具中心使用当前项目的目录、修订号、资料与步骤。右侧还是该项目的原生助手。运行版更新后，使用 DSH 自带的重载功能加载新增路由。

## 问卷

1. 在「问卷设计」填写研究问题、对象、变量、题数及测量维度。「请项目助手起草」把结构化要求填入原生会话草稿。研究者发送后，助手可调用 `ares_workbench` 的 `research` 读取结构，用 `research-proposal` 提交独立建议。本地模板提供另一种可编辑起点。
2. 在设计页添加九类题型、分页及分组。拖拽或用上下移调整顺序，右栏编辑变量、选项和条件。从「问卷说明与设置」修改填写说明与完成提示。「检查逻辑」显示路径错误和需要人工复核的措辞。
3. 桌面和手机预览共用正式定义与答案验证。可换答案测试跳题；运行引擎只接受结构化规则。条件引用之前的题，跳转指向后续页或结束。需要一起满足的条件放在同一组，多个可能同时成立且目标不同的跳转会报冲突。
4. 保存后，从「更多操作」复用模板、打开旧版、运行预测试或正式定稿。预测试沿用项目原有扩展和权限，映射量表、单选和数值变量；可查看排除项、系数与缺失等诊断。问卷路径以填写预览为准。
5. 正式定稿可导出 JSON 与 Word。实际采集后，以变量名为 CSV 表头或 JSON 对象的键导入。单选和量表填选项 ID，数值填数字，多选、排序、矩阵用 JSON 值。导入会核对定稿版、必填、范围、条件路径和来源声明。在「研究产物」看有效数、缺失、均值和选项分布。正式发放可使用导出的问卷定义或文档。

预测试的数据、图表和诊断保留模拟来源。项目内原预测试文件、带模拟标记的文件和已登记的模拟哈希会被实际答卷导入门禁拒绝。实际采集来源由负责人声明，答卷结构由 ARES 检查。

## 访谈

1. 选择「访谈提纲」录入研究问题、方法、对象和背景。选助手起草或本地模板，编辑开场、知情同意、模块、追问、时间与结束语。可调整模块顺序、移动问题并保存版本，导出 Markdown 或 Word。
2. 在「访谈材料」导入笔记、纯文本、SRT、VTT、音视频或创建空白记录。笔记可按「匿名编号＋冒号＋发言」逐行整理。SRT/VTT 及 `[00:00:01.200 --> 00:00:03.500] P01: 发言` 可保留时间戳。手写笔记没有时标时保留为空，也可以把已有逐字稿与登记过的本机音视频关联。
3. 播放器与波形使用保存的媒体，点击时间戳定位。选择一条发言，校订文本和说话人，可标记不确定、关键陈述并记录备注。版本列表保留原始稿和校订稿。原始媒体通过本机项目文件流提供，可在当前记录独立下载原始逐字稿。
4. 在「主题编码」保存一级和二级编码，批量归档或恢复。在校订稿选中文字或整段，关联多个标签；新标注锚定到已保存的原句、字符区间和源版本。助手可以从选中文字提供候选编码，研究者到「研究产物」审阅和采用。
5. 在编码本按文本、参与者或编码检索证据，生成跨访谈对比、频次和 CSV 矩阵。编辑改变原句后，旧证据保留溯源，分析会提示这些标注需要重新定位。模拟文本通过显式选项登记，使用单独的列表和分析范围。

## 本地转写

音视频导入和波形需要本机 FFprobe、FFmpeg。支持 WAV、MP3、FLAC、OGG、M4A、MP4、MOV 和 WebM。浏览器能否直接播放取决于它对文件编码的支持。单文件最多 2 GiB、最长 3 小时，必须有音轨。

在宿主运行环境中提供以下变量。模型和可选引擎由操作者按许可准备到本机。ARES 只读取已配置的绝对路径。

| 变量 | 值 |
| --- | --- |
| `ARES_FFPROBE` 与 `ARES_FFMPEG` | 可选，指向本机命令绝对路径。默认从 PATH 查找。 |
| `ARES_ASR_PYTHON` | 可选，指向实际安装 faster-whisper 的 Python 运行时。默认从 PATH 查找。 |
| `ARES_WHISPER_MODEL` | 预先准备的 CTranslate2 Whisper 目录，至少包含 `model.bin`、`config.json`、`tokenizer.json`。 |
| `ARES_WHISPERX_ALIGN_MODEL` | 可选的本地同语种 Wav2Vec2/CTC 模型目录。需要安装 WhisperX 及兼容的 PyTorch。 |
| `ARES_WHISPERX_DIARIZATION_CONFIG` | 可选的本地 pyannote 管线配置文件绝对路径。配置中的权重也需已在本机准备。 |

基础转写实测环境为 Windows、Python 3.13、faster-whisper 1.2.1、CTranslate2 4.8.4 和已缓存的 Systran small 模型。可选引擎在独立离线进程读本机文件和模型。默认 CPU int8，可选择 CUDA float16，实际 CUDA 依赖由所安装的 CTranslate2 运行时决定。FFmpeg 分段解码，转写生成词级时标。取消或中断后可从同一来源重试，模型、设备、语言与原始媒体吻合时复用已保存片段。说话人自动分离和二次对齐需要额外本地模型与单独验收。

参考许可见[开源来源与许可证](RESEARCH_SOURCES.md)。[Systran small 模型卡](https://huggingface.co/Systran/faster-whisper-small)标明 MIT。[pyannote 社区模型卡](https://huggingface.co/pyannote/speaker-diarization-community-1)标明 CC BY 4.0，需满足模型访问条件和署名要求。研究者应选择与录音语种相符的对齐模型，并根据模型卡核对许可。

## 数据资源

1. 选择 Hugging Face 或 Kaggle，输入可公开发送的关键词并授权本次搜索。
2. 单独授权读取所选数据集的元数据与文件清单。页面展示固定提交或版本号以及提供方声明的许可。在来源页核对许可与访问条件，选文件并审批下载。
3. 下载在后台流式写入临时文件，支持取消与重试。文件完整后检查实际大小、校验提供方可用的散列，并永久登记 SHA-256、来源、版本、许可和下载时间。资料在本机项目内，状态与回执可复查。支持单文件最大 4 GiB。
4. 本机文件可以取用，4 MiB 内的 CSV 或 JSON 对象数组可保存列、缺失与数值字段统计。数据集仍保留外部来源类别，研究者可将带来源的报告绑定到步骤。

身份所需的令牌由宿主环境提供，Hugging Face 使用 `ARES_HF_TOKEN`，Kaggle 使用 `ARES_KAGGLE_TOKEN`。勾选用宿主凭据才读取。项目文件和调用记录存放版本及来源元数据，令牌和有签名的临时传输 URL 留在请求内存。提供方限流、许可或账户失败会显示实际错误状态。

## 版本、流程与宿主

在「研究产物」选择历史版本并绑定步骤。项目节点可回到该固定版本。符合步骤输出格式的内容可写入新工作稿，现有工作文件需手动处理原有内容后再采用。完成步骤依然走 ARES 文件检查及负责人验收。研究记录与后台任务位于项目 `.ares`，通过宿主原项目权限、修订号和事件追溯。

Codex 和 ZCode 插件可通过原有 MCP 的 `ares_project` 使用 `research` 或 `research-proposal`。工具以宿主批准的项目目录为范围。该入口提供设计规范与建议版本。完整问卷设计器、访谈编辑器及数据提供方授权入口在 DSH 研究工具工作台。

## 比赛与作品

在原研究工具页选择「比赛与作品」，按当前需要进入六个子页；右侧仍为宿主原生助手。

1. **比赛要求**：导入项目文件、上传原文或授权读取公开 HTTPS 原文。保留原文件与提取文字的不可变快照。自动识别的段落只是草稿，可手动新增、删除、编辑、映射到当前步骤与作品，也可请原生助手提交整理建议。采用会更新本项目规则清单并恢复待核对状态，不把来源目录或模型建议标为官方认证。
2. **事实与证据**：为数值、结论和口径保存项目文件或研究版本的逐字证据，再关联到作品中的实际原句与章节位置。来源、事实或作品发生变化时显示待核对，并进入原统一项目验收门禁。Markdown/TXT 可预览并确认单处更新，保留原字节及新的工作版本；Word/PPT 按差异在原文档或金山修改后重新关联。
3. **模型实验**：选择项目 CSV/JSON、已登记的数据集或实际答卷，读取字段，选择变量并确认本机计算。固定 Python 引擎提供线性/岭回归和 K-means，保存数据、参数、计算代码指纹与真实结果；可比较方案并用原输入重跑。自定义 Python/R 脚本先展示实际脚本并由负责人批准，固定脚本、数据与参数，再由 DSH 原生 `native-tool` 执行及收集实际回执。ARES 不在 Host 中直接运行任意脚本。
4. **金山回收**：先在金山建立多维表格的表单视图并使用金山现有权限发放，将该文档链接绑定到 ARES 已定稿问卷。读取真实表结构、选择数据表及字段映射；每次授权后分批读取原始记录。必填、范围、跳题路径按定稿问卷检查，答案相同与连续相同作答提示人工复核，不编造耗时或答题者身份。可批量确认无异常答卷、排除结构无效答卷，可疑记录需理由；保留原始快照、排除决定及采用来源。同步后发生改变或新增异常的记录重新复核。软件测试与模拟记录不计实际样本。当前轻量 `.form` API 没有开放答卷列表，因此这里使用确实可读取记录的多维表格表单。
5. **答辩演练**：选择已固定的实际作品版本，连同当前规则原文及项目事实准备材料。助手必须引用这些固定依据的逐字片段提出问题；负责人采用后保存真实回答，再请助手提供有依据的反馈。确认改进意见后加入对应步骤的独立待办，可在答辩页管理，并在项目进度中定位步骤。演练建议和完成待办均不代替作品验收。
6. **跨赛改编**：选择目标比赛、届次、赛道、组别，读取目标流程，将原项目固定作品映射到兼容交付物，预览未覆盖的要求后确认创建新项目。仅复制所选版本的真实字节和来源。原项目、当前工作稿、验收状态及规则基线保持各自独立；新项目的步骤仍待验收。中断时保留可重试清单，不覆盖已被修改的目标文件。

模型通过 `research` 读取具体 `researchId` / `researchVersionId`。需要原文时指定 `researchSourceId`（比赛要求为 `original`，答辩为保存的来源 ID），使用返回的 `nextOffset` 分段读取固定原文。`research-proposal` 支持 `requirements` 与 `defense`，仍只保存待人工采用的建议。Codex/ZCode 使用同一读取和建议协议，完整六项图形编辑器及原生定制脚本派发在 DSH 中。

固定算法需要本机 Python；自定义脚本的 Python 或 `Rscript` 及其依赖需在当前宿主 PATH 中可用。脚本通过 `--input`、`--params`、`--output` 获取固定 JSON 路径，返回含有限数值 `metrics` 的 JSON。脚本、输入与执行计划变化会拒绝运行，未知或失败回执不会成为成功实验。

## 金山账号

项目页头「金山」打开独立账号与协作页面，分别展示 CLI 是否可用、系统密钥链认证以及真实云目录访问结果。认证只在负责人点击后启动金山自身的登录流程，ARES 不接收 Token；项目协作文件夹另行选择。新服务路由需宿主正常重载插件后生效。

## 验证

```powershell
node --test --test-concurrency=1 tests/research-admission.test.mjs tests/research-survey.test.mjs tests/research-interview.test.mjs tests/research-datasets.test.mjs tests/research-browser.test.mjs
node scripts/build_forge.mjs --check
node scripts/build_portable_ui.mjs --check
npm run test:all
```

无头浏览器验收使用真实 ARES 路由、项目文件、浏览器播放器及职能权限。提供方协议与流式验收指向测试拥有的本地 HTTP 服务，线上联网许可仍由使用者在 DSH 中授予。设定 `ARES_RESEARCH_EVIDENCE` 可保留截图。用已有模型及本地测试 WAV 时可另设 `ARES_ASR_QA_AUDIO` 跑实际识别验证。
