## 使用与交互

- 左侧「项目航线」展示实际步骤、负责人、截止时间和验收进度。正常等待前置、工作稿、负责人登记、待验收、已验收分别表达；动画不会推进验收。「管理进度」可设置分工、截止、预计用时及登记工作。
- 中央每颗步骤星核点开详情：目标、负责人、截止、投入、交付物、依赖及原有执行 / 检查 / 验收。技能和提示词收进详情，不挤占主画面。成员黑洞点开显示关联工作与有来源的最近记录，完整记录和历史回放仍可打开。
- 右侧「本地 / 金山云」属于同一作品上下文。已绑定项目文档时默认打开金山真实页面；没有关联时保留原关联入口。本地保存、实际文件变化观察与云稿差异审阅采用仍走原保护机制，不自动互相覆盖。
- 金山页可单独放大，或与本地作品并排对照。切换来源、步骤弹窗、放大及界面重绘不销毁同一网页，避免重置登录、滚动和编辑状态。金山自己的页面负责协同、登录与保存提示；ARES 的「网页已打开」不冒称已保存或已具备编辑权限。
- 底部只留「项目 / 赛事 / 编排 / 能力 / 查找」五项，其他项目管理入口在「更多」。执行动作回到步骤详情。聊天单独常驻，主动收起后通过右侧边缘按钮恢复，原 DSH 会话与输入组件保留。

## 实现与边界

`client/cloud-browser.js` 使用本机已核对的 DSH 桌面公开协议 1：`dshDesktop.browser.acquire / release / onOpenRequested`。按已有 Workspace 的实际 Session 归属选择账号存储分组，不新增工作区；没有权威归属时按实际 Session 隔离。主进程批准的 `name / partition / about:blank#lease` 原生 webview 不注入 Node、preload、DSH 或 Agent 工具，不放宽网页安全策略。Web 环境是明确的 sandbox iframe 兼容路径，站点可能限制内嵌。

`app.js` 将渲染区与持久网页层分离，仅重建普通界面；网页按项目 / 文档保活、定位到实际占位区，详情遮挡时隐藏但不拆除。损坏租约、网页进程退出及引用读取失败可通过刷新重试。提示条留在同一渲染区，并移到导航上方，避免重复和遮挡。

`host/cloud-view.js` 只返回当前已登记项目的官方金山文档引用，保持 owner、同源、POST 门禁；不获取 Token、不改变分享或验收。`host/kdocs-client.js` 兼容已实际观察的 CLI 2.6.1 `id / link_url` 与原 `file_id / file_url`，仍逐一核对文件 ID、HTTPS 官方主机和有界分享链接。

前端入口与路由缓存统一为 `2.3.0-nebula1`，12 个场景模块和 3 个字体继续通过原有自包含资源入口加载，避免重现动态模块 404。执行器、审批上下文、MCP 隔离、人工验收及版本存储的原代码由基线 SHA 审计核对。
