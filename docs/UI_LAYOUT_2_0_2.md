# ARES 2.0.2 助手布局修正

用户截图的问题是原生输入区堆在顶部、助手栏太窄、底部大面积闲置。此前离线“服务未加载”检查没有覆盖真实原生布局，不能作为完整视觉验收。

## 改动

- 使用实际ARES容器的宽高查询，避免DSH侧栏占用宽度后仍按整个桌面viewport排三栏。
- 助手正常宽400px，中等容器保留380px；步骤改横向导航以保留编辑空间，助手跨越步骤导航行取得完整高度。
- 窄容器使用“流程编辑 / ARES助手”切换，助手占满可用宽度；宽面板提供展开和还原。
- 原生slot祖先链、ConversationContent和滚动容器撑满高度，composer通过margin-top:auto及原生sticky行为贴底。
- 输入文本最大高度随实际聊天容器变化，长输入内部滚动，不把底部工具栏挤出画面。
- 暗色采用中性石墨灰，去除绿色大底和重复嵌套边框；精简顶部说明，增加空对话的实际操作起点。
- 原生编辑器挂载点保持，切换步骤与面板不会主动重建对话。模型、工具和发送仍由DSH提供。

## 验证边界

独立布局环境执行了已安装DSH的ConversationContent函数和对应CSS，并调用实际ARES的NativeEditorBody生成空态；输入工具栏及会话数据明确为布局夹具，不是实际在线DSH会话。
使用隐藏浏览器观察宽、窄、暗色、浅色、长内容、长输入、展开、切换步骤、配置保存和短高度场景。配置保存走真实ARES API，数据位于隔离ARES_HOME。
