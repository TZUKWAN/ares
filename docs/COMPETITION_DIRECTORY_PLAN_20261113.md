# 用户管理比赛与赛道

目标：运行版 ARES 的比赛/赛道可由用户新增、删除、改名；内置和自建都能管理，支持恢复误删。保留比赛赛道分类、现有流程编排/项目推进/常驻助手及原验收、审批和 MCP 隔离；不改 METIS、不操作用户窗口。

|单元|文件与动作|完成标准/验证|
|---|---|---|
|D1 持久化目录|新增host/competition-directory.js；catalog接合并层、competition-workflows保留历史范围|独立修订/锁/原子保存；增删改恢复真实读回；内置数据不改；跨目录重复/旧修订/无效参数拒绝；旧项目/流程字节保持|
|D2 运行版入口|routes增加原owner门禁下目录读写；编排计划使用显示名但固定身份保持|实际API读写与权限/请求校验、已有流程保存和项目固定版本、空目录可恢复|
|D3 管理界面|同一选择区“管理比赛与赛道”，统一现有表单/弹窗风格|真实按钮新增/改名/删除/撤销/刷新持久化；标签无注入，390/1280布局可用；本地未存流程和聊天保持|
|D4 加载与交付|原自包含构建、必要导入版本、状态与审计|相关检查通过，源码/生成物/保护文件复核；不扩大到其他插件或不相干功能|

技术路线：在当前ARES home保存轻量覆盖层，不覆盖安装包data/*.json。比赛ID、赛道内部键稳定；改名修改显示名称，避免流程引用失效。删除仅从可选目录移除，保留已存流程和原项目；恢复后能找回同一流程。配置验证允许历史归属，实际新建/编排选择只接受当前可选项。新增赛道的作品方向沿用现有领域；未核对的比赛仍采用真实规则待确认起始草稿。

风险：删除当前项或全部条目导致空值、编辑草稿被刷新覆盖、两个窗口并发、目录删除使旧配置失效、赛道改名丢流程、宿主旧模块缓存。对应验证不使用线上模型或云端写入，不代用户增删实际目录。

交付：直接修改的运行源码、用户可见管理入口、对应真实本地/API/浏览器测试及说明。工作基线与关键源码备份在本聊天work/ares-competition-directory-20261113。
