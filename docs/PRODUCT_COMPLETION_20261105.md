# ARES 操作闭环完善计划

目标：运行版直接实现节点一键执行、引导构建流程、云稿审阅采用和作品版本对比；逐项接真实行为并验证，再继续规则、扩展、预测试和计划管理。保持用户既有改动、人工验收及MCP隔离，不改METIS、不另起DSH、不控制窗口。

| 单元 | 目标/文件 | 执行与验证 | 完成标准 |
| --- | --- | --- | --- |
| P1 | host/node-execution.js、routes/index、client工作台 | 按固定项目/节点建立或复用DSH原生会话、提交真实prompt，保留运行记录、查询/停止；实际文件检查与工作版本；对应本地检查及当前Host真实调用 | 点节点执行后确有原生工具/实际产物，结果等待验收；重复/人工/缺前置/错误会话拒绝，取消不冒充完成 |
| P2 | workflow-builder、app/表单与路由 | 目标/领域/材料与交付要求生成可审阅流程，自动给实际技能、依赖与有效路径；保留草稿/旧项目；人工审阅后正式保存 | 新流程真实校验、保存、建项目并执行；不拿固定模板回显冒充AI生成 |
| P3 | cloud-candidates、collaboration与项目工作台 | 云文本候选登记不可变对象，预览差异后显式采用到指定文本作品；保留旧稿、云来源与失效节点；实际CLI拉取/采用验证 | 本地实际文件与新工作版本一致，旧稿可追溯；冲突/来源/格式/模拟数据门禁不变 |
| P4 | artifact-diff、project-workbench与UI | 两版作品/项目、当前稿与历史内容对比，新增/删除/修改与受影响节点可读；文本逐行/二进制指纹清楚显示 | 实际文件差异和历史对象一致，损坏/越权拒绝；界面真正可选可看 |
| P5 | rule-checklist/model、projects、材料页 | 负责人逐项确认绑定实际证据和规则基线指纹；变化失效；必需项阻断提交，建议项仅提示 | 文件/规则证据与人工确认门禁、提交检查及DOM实际读写通过 |
| P6 | extension-packages/form、node-execution与UI | 固定包导入导出不复制宿主授权；实际工具目录和普通参数表单；真实跨项目接口执行与原生子插件交接 | 包/typed input/重新授权真实生效，固定原生子插件真实回执及工作版本形成 |
| P7 | survey-experiments及UI | 多种子/样本量/场景组合实际计算，保留每组CSV/诊断，结果表与历史回读 | worker和生产路由DOM真实计算通过，模拟标识及正式验收门禁保留 |
| P8 | project-plan及UI | 项目/节点截止、分工/预计用时、个人待办及逾期/72小时/阻塞提示；仅工作台内提示 | 日期/队员门禁与实际文件保存/重开UI回读通过，不改验收 |

技术路线：复用DSH SessionController.prompt和原生审批，无自建模型循环；所有项目写入继续revision+锁，工作稿/固定对象/验收分别留证；云接口只用官方CLI且只碰已授权测试文档。界面常用操作表单化、直接提供下一步，技术JSON折叠。

主要风险：真实模型/外部接口失败、用户并发编辑、未知写入回执、不同Office格式不应按文本覆盖。必须保留失败/旧字节、明确冲突并复测；操作成功不自动等于内容验收成功。交付包括运行代码、精准检查、当前Host/云实际回执、状态记录及最终源码审计。
