# ARES 2.1：统一竞赛项目工作台

竞赛项目是唯一主记录。流程节点直接引用作品工作版本、已验收版本、输入、复核、负责人和项目事件；作品版本不再是另一个主导航。

## 日常使用

1. 打开“竞赛项目”，创建项目，选择真实目录、赛事、赛道和流程。重点赛事可显式选用带官方出处的参考；这不会自动完成当届规则核验。
2. 在节点卡片查看目标和交付物，安排队员，通过“继续项目助手”进入DSH原生会话。ARES配置助手仍使用固定编辑会话，不要求另选工作区。
3. 生成实际文件后，可先“保存作品工作版本”；实际检查、内容复核与人工节点确认仍是独立验收条件。
4. “固定项目版本”提供工作快照、阶段版本、提交版本。阶段须包含已验收节点及其前置；提交须整套节点和当届规则通过原检查。
5. 恢复历史版本会创建“恢复工作稿/…”并切换工作稿输出目录。当前文件、旧提交版、历史和实际对象均保留，恢复节点重新复核。

流程配置的基础页只显示名称、目标和主要交付物。执行方式、输入字段与依赖折叠在高级选项；提示词、技能、参数和产物契约仍可展开编辑。支持从基础模板新建、复制、排序、归档到空及恢复。配置保存仍采用提案检查、当前修订号和一次明确保存；旧项目不自动跟随新模板。

## 文件与验收

- `.ares/project.json` 同时保存流程状态、队员、作品版本引用、里程碑、扩展授权引用和事件引用；所有新写操作检查项目修订号。
- `.ares/objects/` 保存实际字节；`.ares/artifact-versions/`、`releases/`、`events/`、`extension-runs/` 保存带内容指纹的记录。
- 作品版本包含真实文件、目录、输入版本和复核引用。源代码中的空文件也保留。原目录验收指纹兼容保留，新验收另检查完整文件树；新增空文件同样触发复核。
- 文件、事实、前置结果或复核变化会使验收失效。损坏历史拒绝读取，不用最新版填补；历史列表显示异常，其他工作区仍可浏览。
- 历史恢复保护的是记录下来的项目作品和流程数据，不能替代操作系统、DSH、外部工具、依赖与全局技能版本的独立备份。

## 金山协作

适配本机 `kdocs-cli`，本轮实际读取的版本为2.6.1及其官方Skill命令资料。ARES不接收Token，不调用自动登录或升级；只有用户明确点击选定工作稿“开启链接共同编辑”时，才公开该工作稿的可编辑链接。

先让本机金山CLI具备个人账号登录，再在项目“协作设置”浏览并选择项目文件夹。支持子目录、返回、目录与工作稿分页；技术ID仅在高级选项中手填。按钮实际读取目标目录后才登记绑定。绑定表示曾验证过目标；每次云操作仍需真实有效的账号权限。本版个人账号CLI不等于企业WPS365支持。

- 浏览绑定目录，选择直接子文件，关联流程作品；协作链接从实际文件信息取得，无需手填；仅关联文档不改变分享，开启链接编辑是单独的明确操作。跨项目、未登记文档ID不能经ARES读写。
- 查看真实云端历史，直接显示版本、时间、修改者和备注并支持继续翻页。拉取功能读取服务器转换的文本，并在读取前后核对云文件版本；结果存入“协作候选/…”，需要本地复核后采用；同字节候选可复用，本地已修改时另建新候选并读回核对，不覆盖队员编辑。它不是原Office文件、历史二进制下载或自动合并。
- 常用协作方式是选择工作稿后点击“开启链接共同编辑”。仅该工作稿设置为anyone和真实editable角色，写后独立核对并返回实际链接；不用逐人找账号，不开放文件夹或作品归档。成员定向授权接口保留为可选能力，不再是完成协作的必需步骤。
- Word工作稿提供原生“批注”，可指定真实段落；先读取既有批注，再写入并独立核对内容，处理Word自带的末尾段落标记。结果不明保留凭据，相同请求只读核对，不重发。其他文档保留底部留言接口；被文档作者关闭时明确提示，不能将批注成功冒充底部留言已开启。
- 阶段发布将固定真实文件和公开的版本清单打包为一个ZIP，负责人上传新副本。独立核对文件ID、云盘、名称、大小、目录和云版本，并取得实际归档链接；不覆盖共同编辑中的文档。结果不明时保留预期名称及回执，通过“核对发布记录”查询，禁止自动重传。核对未完成时保留原上传回执；已知文件ID不能被另一个同名同大小文件替代。在本机同一ARES服务内，真实在途发布请求会拦住重复发布、核对与目录切换，结束后才放行。
- 发布先独立读回元数据；“核对归档完整性”进一步从本地固定对象重建完全相同的ZIP，核对原发布SHA256、云版本、大小与服务端存储校验和。临时下载地址仅在CLI内存中处理，不保存；这个检查不是逐字节云下载。项目清单不上传本机绝对路径、账号凭据、全量事实或DSH原生标准插件声明。

云文档工作稿负责多人编辑；ARES负责人冻结项目里程碑。该机制不声称提供多人同时修改项目JSON的分布式事务、跨文档原子提交、冲突自动合并或实时代码协作。

## 子插件构建与预测试

在项目“构建子插件”选择HTTPS JSON接口或DSH原生工具，填写名称和目标。常规表单可以完成登记；高级清单可声明输入输出约束、响应路径、请求头环境变量引用和固定工具参数。已构建子插件可通过“用于节点”绑定当前固定版本，在节点卡片直接运行；绑定与扩展版本引用随里程碑一起记录，恢复时不自动恢复旧权限。实际清单包写入项目 `.ares/extensions/packages/`；真正执行授权另存宿主 `ares-extension-authority.json`，绑定项目真实目录、项目ID、子插件和清单指纹。项目中的启用标志或复制项目不能代替宿主授权；版本变化需要重新启用。

- HTTPS接口固定目标，检查DNS并固定连接地址，拒绝本地/私网/保留地址、重定向及URL内密钥。POST发送JSON；GET支持简单查询字段。DNS、连接和响应共用30秒总时限，取消后不会再启动后续请求。密钥只通过配置的环境变量名称引用。失败返回失败记录，不生成备用假结果。
- 原生工具扩展只能在项目助手中执行，经DSH实际工具目录、权限、父调用令牌、取消和原生日志转发；工作台Host不直接运行外部脚本。没有可见工具时失败，不绕过MCP隔离。
- 后台原生任务保留原jobId，由原助手 `ares_extension action=poll` 跟踪，不重复启动。中断或丢失回执只能在负责人实际核对停止后登记为中断待核对，不能标成功。
- 每次运行保存固定清单、输入指纹、实际结果、状态与来源。运行成功不自动完成竞赛节点。

“问卷模型预测试”内置能力实际生成带seed的CSV，支持量表、数值、分类、二元题，独立潜变量及量表/数值载荷，缺失率与低一致性场景；计算样本统计、成对相关、量表Cronbach alpha和可选OLS诊断。基础表单每行输入“题目 | 级数 | 因子”；高级参数见[示例清单与输入](EXTENSION_EXAMPLES.md)。自定义数学模型可经已启用DSH工具扩展运行。

所有生成数据明确为 `synthetic`，真实样本数为0，存入独立“预测试/”目录；内容指纹、CSV来源列和来源记录会阻止改名复制后充当正式证据。来源链也保留模拟类型。该机制不能推断所有外部人工改写文件的真实来源；专业内容与真实采集仍须团队核验。模拟相关和样本内拟合不能证明真实效度、预测能力或参赛结果。

## 本轮真实验证与限制

2.1.2在既有PID64880和同一ARES Agent，使用已配置DeepSeek实际运行原生Auto审批回合；11项检查通过，配置服务标识、ares_config_read/write/read/pwsh实际回执及退出码0均已核对。没有补造审批头/步骤/调用；开发验收未调用Kimi，原会话模型选择已恢复，全局默认未改。普通使用继续采用用户在DSH选择的模型；这次实测不等于所有模型或每个外部MCP都已逐一执行。

按用户最新意图，验收Word实际开启链接可编辑，目录与ZIP仍私有；Word批注实际写入并独立读回，同一次写入的回执检查器对末尾CR处理错误已修，通过只读核对恢复，未重复发送。真实私有ZIP已核对存储SHA1与本地固定版本，源归档SHA256一致；原始下载仍需登录态，不声称下载过。底部全文留言仍被作者设置关闭，新的Word批注是单独的可用入口。

本轮普通Node、真实文件、无窗口DOM和云协议检查有对应日志。协议夹具不是云成功或专业竞赛成果；实际Host与云回执单独保留。未另起DSH、未操作窗口、未改METIS，验收与MCP隔离保留。

数学建模、创新大赛高教主赛道、服务外包参考包含已读取官方出处；软件杯官方入口访问超时，仍标未核验。132项赛事目录不等于逐项当届验收。更详细命令、文件指纹、问题与边界见本轮交付报告。

## 异常恢复与检查边界

关闭读取或运行对话框会取消该请求，迟到结果不会重新打开弹窗；已发出的外部写入结果不明时仍保留待核对记录。模拟计算使用固定计算线程，可取消，不推进正式验收。

保存锁记录真实进程归属。确认原进程不存在后，恢复操作保留旧锁证据，并用随进程退出释放的系统互斥避免多个恢复者相互覆盖；活进程、无法确认的进程和不明旧锁均保留。原子锁发布使用同目录硬链接，已在本机NTFS验证；不支持该能力的文件系统会明确拒绝保存，不绕过互斥。系统互斥依据[本机Node版本的libuv实现](https://github.com/nodejs/node/blob/v25.6.0/deps/uv/src/win/pipe.c)。

已知格式扩展名须与产物声明一致，修改文件路径时界面同步格式。Office检查前限制解压条目与大小；CSV逐行核对列数并设扫描预算，XLSX/PDF/图像也有明确上限。超过预算会返回具体原因，不把未检查内容当作通过。凭据文件不能作为作品、预览、正式资料或规则快照。

“全部项目版本”和“作品历史”提供可读的文件、节点与状态；技术记录折叠展示。恢复始终建立新工作稿，仍需重新验收。

## 2.2闭环补充

节点执行现在通过原生prompt实际运行，副本与验收分别保留；节点本身不再只登记开始状态。引导构建、云稿审阅采用和版本内容比较已接实际文件。规则条目确认绑定届次/范围/原文和实际证据，证据变化自动要求重验；编辑核对元数据不会使未改变的作品反复失效。子插件包可跨项目复用但不复制宿主授权；简单输入约束自动生成普通字段，复杂结构保留高级JSON。预测试可以对多个场景/种子/样本档位分组实际计算并比较，最多12组，总样本×题目100万；模拟数据仍不得当作正式材料。

项目截止与节点时间、预计用时、队员待办以及逾期/临期/阻塞汇总已加入，只在工作台显示。不提供多人项目JSON自动合并或跨电脑状态实时同步。详细操作、验证范围和限制见[2.2完善计划](PRODUCT_COMPLETION_20261105.md)。
