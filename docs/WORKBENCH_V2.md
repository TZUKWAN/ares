# ARES 2.0 实现与验证边界

## 模块

- `host/catalog.js`：目录、流程校验、修订号配置、固定版本和资源清单。
- `host/projects.js`：项目事实、任务依赖、产物检查、复核、失效传播、资料/规则与差异升级。
- `host/runtime.js`：固定会话内的 `ares_project` / `ares_library`，按步读取及人工节点限制。
- `host/native.js`：实际桌面接口的原生模式声明，独立命名空间与历史版本。
- `host/assistant.js` / `editor-workspace.js`：DSH 原生编辑会话、服务器管理的固定通道、草稿与提案桥接，无自写模型循环。
- `host/editor-runtime.js`：专用原生预设及 `ares_config_read` / `ares_config_edit` 配置工具。
- `host/routes.js`：真实 API、方法/来源/大小检查和静态资源。
- `client/app.js` / `style.css`：全新 DOM 工作台，React 适配器仅负责宿主容器与生命周期。
- `client/editor-session.js` / `client/client.js`：原生会话创建/保留、SessionProvider、嵌入式消息区及元数据同步。`hero=false`，不显示工作区选择；原生挂载点在编辑重绘间保留。
- `scripts/ares.mjs` / `inspect_artifact.py`：CLI 与真实文件结构解析。

## 不变量

1. 保存检查修订号，无效技能、越界路径及前向依赖不能保存。
2. 项目不会静默升级；明确采用后才更新，原定义与历史保留。
3. 任务须满足依赖，完成需要当前产物和复核哈希；输入、产物或复核变化后重新验收。
4. 章节检查父文档，可选缺失不阻断，条件输入未知不静默忽略。
5. 模型不能确认团队调查、实验、实物测量及平台作业。
6. 结构、程序运行、内容判断、版式和主办方规则的核验分别记录。
7. 缺模型服务、解析器或实际文件时返回明确失败，不产生模拟成功结果。

## 旧能力修正

重写16个旧技能并新增12个分步能力，去除固定七阶段总控、跨领域商业必填、统一文体和无依据评分要求。
财务脚本移除通用数字与利润调节，要求来源和期初平衡，真实计算三表并报告资金缺口。
旧评分矩阵区分明确硬性点与质量建议，结构审计取消固定图片/表格/网页数量。旧 `formal_ready` 不再因结构检查通过变为真。
旧脚本保留兼容用途；当前入口以原生项目工具与 `scripts/ares.mjs` 为准。

## 2.0.1 原生编辑会话修正

替换2.0.0的自制共创聊天，完全交由DSH管理模型和对话。后端生成编辑通道ID，不要求浏览器提供workspaceId。
会话必须经DSH实际inspect核对编辑预设与固定cwd；旧会话响应不能覆盖新对话，切换流程不新建会话，人工草稿变化使旧提案失效。
运行中宿主已作只读检查：检查时仍加载2.0.0旧助手接口，本轮未重启或重载。协议测试采用明确的原生服务夹具；离线浏览器测试使用真实ARES路由，不能冒充在线DSH验证。

## 2.0.3 原生工具能力修正

编辑与比赛预设同步当前 DSH 完整标准工具组合；编辑运行时不再设置空白名单。实际 Agent 目录及最终模型 wire 目录均核验，尊重宿主的项目专用 MCP 隔离。重连时升级空闲编辑会话的旧预设作用域，保留会话与提案；运行中不改绑。30 项编辑/API 回归与8项真实 DSH 服务集成检查通过，具体环境、命令、实调用及在线边界见 [工具修正说明](NATIVE_TOOLS_2_0_3.md)。此前55项是2.0.0历史验证结果，本轮未重复无关测试。
