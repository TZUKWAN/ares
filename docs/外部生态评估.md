# Ares 外部技能与 MCP 生态评估

评估日期：2026-10-02

原则：只引入能说明来源、许可证、依赖和权限边界的组件；默认不自动启用会访问外网、内网、账号或用户文件的 MCP；第三方技能只作为参考，未经源码/许可证审计不复制执行代码。

## 已采用

### Microsoft Playwright

- 来源：https://github.com/microsoft/playwright
- 用途：原型页面运行时加载、浏览器控制、截图、页面错误和控制台错误记录。
- 许可证：仓库页标注 Apache-2.0。
- 集成：`skills/ares-prototype/scripts/smoke_prototype.py`，作为 `scan_prototype.py` 的运行时补充；优先使用 Playwright 浏览器，缺少时回退到本机 Chrome/Edge；不访问远程页面。
- 验证：round1 原型 10 个页面全部加载通过，生成 `smoke-manifest.json`。
- 边界：Playwright 浏览器不是核心依赖；未安装时必须在交付清单记录“未完成运行时验收”。

### Microsoft MarkItDown

- 来源：https://github.com/microsoft/markitdown
- 用途：将用户提供的 DOCX/PPTX/PDF/XLSX 等材料导入 Markdown，便于证据摘录和旧材料迁移。
- 安全策略：调用 `MarkItDown(enable_plugins=False)`，不启用第三方转换插件，不注入模型客户端，不自动访问远程服务。
- 集成：`scripts/ingest_material.py`；纯文本/Markdown/CSV/JSON 使用本地确定性回退，未安装 MarkItDown 不影响核心生产线。
- 输出：导入 Markdown + SHA256 + MIME + 转换器信息，便于写入 evidence artifact。
- 边界：MarkItDown 当前环境未安装，Word/PPT/PDF/XLSX 的增强导入尚未在本机实测；已实测本地文本回退。
- 2026-10-05 安装复核：尝试安装官方 `markitdown` 包时，其 `magika` 依赖的 `onnxruntime` 下载受代理超时影响，安装未完成；未把半成品依赖留在环境中，确定性文本回退仍可用。

## 评估后暂不自动集成

### 官方 MCP Fetch Server

- 来源：https://github.com/modelcontextprotocol/servers/tree/main/src/fetch
- 优点：把网页内容提取为 Markdown，适合调研来源导入；MIT 许可证。
- 风险：官方文档明确提示可访问本地/内部 IP，可能形成内网暴露；同时当前实现要求 MCP SDK 1.x，版本迁移仍在进行。
- 决策：不在 Ares 插件中自动启动。若用户自行配置，必须增加域名 allowlist、禁止私网地址、请求超时、响应大小限制、robots 遵守和原文哈希；当前 Ares 先使用受限 URL 检查和本地证据归档。

### PptxGenJS

- 来源：https://github.com/gitbrent/PptxGenJS
- 优点：图片、媒体、Speaker Notes、HTML 表格转幻灯片能力较丰富。
- 决策：暂不替换现有 python-pptx 引擎。当前引擎已有图表轴 ID 修复、图片/Demo 页、严格混量纲门禁和 PowerPoint 独立渲染证据；贸然更换会扩大回归面。后续仅在需要 Speaker Notes 或媒体嵌入时做隔离适配器评估。

### 社区技能市场的 presentation-research 等技能

- 来源示例：https://skillsmp.com/creators/js2iiu-mh/agent-skills/github-skills-presentation-research
- 决策：不直接复制。页面展示了完整调研→PPT 工作流思路，但来源、许可证、依赖和执行代码需要逐仓库审计；Ares 只吸收“多来源研究日志”和“参考文献页”这类流程思想。

### 插件目录检索结果（2026-10-02）

已按插件管理规范检索浏览器工作流、学术检索和演示文稿能力。目录返回 TinyFish、Consensus、scite、Gamma、Genspark AI Slides、Vercel 等候选，当前均未连接到本任务。

- TinyFish 可做用户指向的浏览器流程，但它引入外部浏览器会话与更宽的站点访问边界；Ares 已有本地 Playwright 和受限 URL 检查，暂不叠加。
- Gamma/Genspark AI Slides 能快速产出外部演示稿，但会绕开 Ares 的单一事实源、图片来源、OpenXML 轴校验和 PowerPoint 独立渲染门禁；暂不替换本地 PPT 引擎。
- Consensus/scite 对学术检索有价值，但需要用户连接外部服务，且不能替代 Ares 对项目市场、政策、竞品和赛事章程的证据台账；保留为以后用户主动连接时的可选适配器。
- Vercel 属于外部部署能力，当前用户要求的是本地可运行 Demo 和可验收产物，未引入部署权限或网络依赖。

结论：本轮没有自动安装或连接任何第三方插件；所有新增能力均保持在本地、可审计、可回归的 Ares 目录内。

## 已采用的工程原则

- 参考 OpenAI 插件技能文档的“技能负责流程、MCP 负责受控工具、技能按渐进披露拆分”原则：https://developers.openai.com/plugins/build/skills
- Ares 将复杂流程拆为 `commands/ares.md`、`ares-run.json`、`build_scorecard.py`、证据门禁和独立渲染脚本；低上下文模型每轮只读取当前阶段、下一动作和阻断项。

## 本轮实际落地的确定性护栏

- `scripts/doctor.py` 先写入必需/可选模块、Office/浏览器路径和能力状态；缺失的可选能力会被记录，不会被模型默认为可用。
- `scripts/match_competition.py` 只读取 `competitions.json` 与 `tracks.json`，最多返回 3 个候选、推荐赛道和交付物预览；未知需求输出低置信度警告。
- `scripts/audit_visuals.py` 只依据真实 Word/PPT/原型文件统计图片、表格、图表、图题、Demo 标识和页面数，并给出 L1-L6/E1-E3 的推荐视觉槽位；`--strict` 阻断缺失项。
- `scripts/smoke_low_context.py` 只串联真实状态文件、目录匹配、环境记录和已有档案门禁，不模拟模型回答或伪造参赛产物。
- 当前环境已通过 Playwright 10 页面运行时冒烟；持久化 BrowserContext 的 viewport/new_page API 适配已修复，运行时 manifest 已真实生成。MarkItDown、LibreOffice 仍是可选未安装能力。
