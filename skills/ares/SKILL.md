# Ares 总控路由技能

Ares 是大学生学科竞赛与创新创业竞赛的超级插件。用户只需一句话需求，本技能负责把需求解析成赛事、赛道、档案与生产计划，并调度生产线技能完成全套材料。核心逻辑全部固化在本文件，各平台（支持或 Commands/Agents/Hooks 与否）均可通过自然语言触发本技能，功能不打折。

## 零、单一事实源原则（全局强制）

所有产出物从同一份 `project.json`（Project Profile，结构见 `references/profile-schema.json`）生成。任何产出物中的关键数字必须先查此文件；文件中没有的字段由生成方回填档案后，其他模块方可引用；`data_confidence`（real/estimated/placeholder 三类）全程维护。改档案后执行同步流程（第八节）。

## 一、执行步骤（七步流程，固化）

### 1. 赛事匹配

读取 `data/competitions.json`（132 项主库），按以下优先级匹配：

1. 用户明确说出赛事名或别名 → 精确匹配 name/aliases 字段（如 互联网+ → 中国国际大学生创新大赛）。
2. 用户描述赛事特征未给全名 → 关键词匹配（主办/领域/赛制特征），给出 2-3 个候选请用户确认。
3. 用户只说学科或项目类型，未说赛事 → 按学科关键词推断 pipeline，给出该线 2-3 项推荐（按级别与专业匹配度排序），请用户确认；用户表示随便/帮我选时，直接推荐匹配度最高的一项并说明理由。
4. 完全无法匹配 → 询问用户所在学科与赛事全称。

匹配结果记录 `competition.id/name/level/track`。

### 2. 加载赛事画像

读取 `data/rubrics/{id 三位}.json`（评审维度、权重、提交物、流程）与 `data/tracks.json`（该赛事条目：pipeline、默认产出物、交付目录）。据此确定：生产线路、产出物清单、评审权重高的维度（后续写作与 PPT 页序调整的依据）。rubric 缺失时以 tracks.json 默认产出物继续，并在交付说明中注明。

### 3. 一次性信息采集（只问一轮）

一轮问齐以下信息，用户未答的项标 placeholder 后继续，严禁反复追问：
项目名称、一句话简介、赛道选择、团队成员与分工、指导老师、已有成果（专利/论文/试点/获奖）、真实经营数据（如有）、截止时间。

信息充分的场景（用户首句话已含大部分要素）可跳过提问，把缺失项直接登记为 placeholder 并告知用户可随时补。

### 4. 建立 Project Profile

把采集信息写入工作目录 `project.json`，运行：

```
python <插件目录>/scripts/validate_profile.py project.json
```

向用户确认档案摘要（项目名、赛事赛道、团队、成果、数据登记情况）。placeholder 项在摘要中显著标注。

### 5. 生成生产计划

按赛事产出物清单列出将交付的文件树与批次顺序，格式：

```
批次一（调研）：市场/政策/竞品调研笔记 → 回填 project.json
批次二（并行）：01-商业计划书.docx ｜ 02-财务三表.xlsx ｜ 04-项目原型/
批次三（依赖计划书）：03-路演PPT.pptx ｜ 07-路演讲稿
批次四（收尾）：08-答辩QA预案 ｜ 10-评审报告 ｜ 11-数据真实性清单
```

获得用户确认后执行；用户催促或明确要全套时，视为已确认直接开工。

### 6. 编排生产

调度依赖关系：调研先行；计划书、财务表、原型、代码可并行；PPT 与讲稿依赖计划书内容；评审最后。每条生产线的具体规范见对应技能（ares-entrepreneurship / ares-modeling / ares-engineering / ares-business-case / ares-art-design / ares-coding-contest / ares-humanities / ares-lab-skills / ares-simulation）。所有文本产出强制引用 ares-writing-style；原型遵循 ares-prototype；PPT 遵循 ares-ppt；数据遵循 ares-data。

### 7. 质检交付

1. 一致性扫描：`python <插件目录>/scripts/consistency_check.py <输出目录> --profile project.json`，零矛盾才可交付。
2. 模拟评审：执行 ares-judge 技能，按 rubric 维度打分，输出《10-评审报告.md》。
3. 自动修复高优先级扣分点后复检。
4. 输出交付清单与《11-数据真实性清单.md》（区分【用户提供真实数据】【AI估算】【占位待填】三类）。

诚信护栏（全程强制）：模拟/合成数据在文件头部与交付清单标注 DEMO；严禁虚构专利号、获奖记录、合作协议；论文类产出提示查重与 AIGC 检测风险；引用数据必须带出处与年份。

## 二、单项模式

用户只要单项产出时跳过全流程：已有 project.json 则直接进入对应生产线（/ares-bp、/ares-ppt、/ares-prototype、/ares-review）；没有档案则先执行流程 1-4 建档再生产。/ares-sync 见第八节。

## 三、输入

- 用户自然语言需求（一句话即可）。
- 可选：已有 project.json、已有材料（旧版计划书、论文草稿、数据文件）。

## 四、输出

- 工作目录：`project.json` + `输出/项目名/` 下的全套交付物（按 tracks.json 目录结构编号）。
- 交付清单.md：文件树 + 每件一句话说明 + 使用建议。
- 数据真实性清单.md：三类数据登记。

## 五、质量自检清单

- [ ] 赛事匹配结果与用户确认过（或用户明确授权自动选择）
- [ ] project.json 通过 validate_profile.py
- [ ] 全部产出物数字与 project.json 一致（一致性扫描零矛盾）
- [ ] 全部文本通过 ares-writing-style 自检（机扫 + 人工）
- [ ] 评审报告有维度/得分/权重/扣分点/建议/证据位置
- [ ] DEMO 数据全部标注；数据真实性清单三类齐全
- [ ] 无虚构专利号、获奖记录、合作协议

## 六、完整示例对话

用户：我要参加中国国际大学生创新大赛，项目是毫米波雷达独居老人跌倒监测，5人团队，2项专利，3个社区试点。

助手执行：赛事匹配 → 中国国际大学生创新大赛（id 1，A1，高教主赛道默认）→ 读取 rubrics/001.json（评审五维度权重）与 tracks.json（L1 线，11 项产出物）→ 信息采集确认一轮（补问：学校学院、指导老师、目标定价、截止时间；用户答部分，其余标 placeholder）→ 写 project.json 并校验通过 → 给出生产计划（四批次文件树）→ 用户确认 → 并行生产 → 一致性扫描零矛盾 → 模拟评审 87 分 → 修复 2 处高优先级扣分点复检 89 分 → 输出交付清单与数据真实性清单。

用户：帮我准备数学建模国赛，练一套往年A题。

助手执行：匹配 全国大学生数学建模竞赛（id 5，A2）→ rubrics/005.json → L2 线（ares-modeling）→ 采集：几人队伍、编程语言偏好、目标奖项 → 建档 → 按赛题解析→假设→建模→求解→论文→灵敏度→摘要精修流程产出论文+代码+数据+图表 → 质检交付。

## 七、与其他技能的协作接口

- 调用：九条生产线技能、ares-writing-style（强制）、ares-docx、ares-ppt、ares-data、ares-prototype、ares-judge。
- 数据契约：向生产线传递 project.json 路径与赛事画像（rubric 权重 + 产出物清单）；生产线回传产出文件路径清单。
- 被 commands 六个入口调用；agents 五个子智能体在生产步骤中被调度。

## 八、变更同步（/ares-sync 逻辑）

project.json 变更后：读变更字段 → 找出引用该字段的产出物（关键数字来源登记在产出物生成日志中，未登记的按全部产出物处理）→ 重渲染受影响文件（财务表重跑 build_financials.py，PPT 重跑渲染脚本，计划书与讲稿重写含该数字的段落）→ 重跑一致性扫描至零矛盾。

## 九、平台适配

支持 Commands 的平台：六个命令入口直接可用。不支持的平台：本 SKILL.md 即完整逻辑，自然语言触发即可。支持 Hooks 的平台：on-project-init 在建档时自动创建目录骨架（见 hooks/on-project-init.md）；不支持的平台按该文件内的手动指令等价执行。
