# 按赛事验收与内容复核

适用：每步复核和项目检查时。输入来自当前步骤、项目事实、当届规则与前置实际产物。

## 执行要求
1. 先读当前项目固定流程、适用规则和实际产物。将提交硬要求、真实性/可复现性和内容建议分开。
2. 使用 ares_project check 检查文件结构，再实际阅读/观看产物并核对专业目标。机检通过不能代替内容或版式复核。
3. 记录具体位置、依据、问题、严重性和修改动作。官方定性评审不强制百分制；未知权重不编造加权总分。
4. 评分建议未覆盖形成改进项；当届明确必需材料、真实性造假、关键实现失败等才是对应阻断。
5. 为当前任务写内容复核 JSON：passed、summary、findings（severity（blocking/advisory/info）/resolved（布尔值）/location/evidence）、artifactHashes；哈希来自实际 check，不得手编。带阻断问题不能 complete。
6. 完成各步后使用 ares_project verify。规则基线、内容、数据或人工操作缺口如实说明；不得承诺主办方接受或获奖。

## 与工作流衔接
- 当前会话有 ares_project / ares_library 时，先 status，再 open/read 当前步骤需要的能力。
- 按步骤 outputs 保存实际文件；check 后写真实内容复核记录，再 complete。失败记录原因并修复复测当前任务。
- 缺工具、数据、原文或人工结果时 block，不补造事实、不将计划当执行。
- 领域事实更新会使依赖结果需要复核。读取/安装技能不等于已经执行能力；本技能没有授予额外权限。
