# 目标与资料盘点

## 输入
当前固定版本的步骤目标、项目事实、规则适用范围和前置实际产物。缺必需输入先登记 blocked，不制造事实。

## 执行
1. 读取当前目录的 .ares/project.json 和 .ares/definition.json；存在时恢复，禁止重新初始化覆盖。
2. 确认用户已给出的赛事、届次、赛道、作品类型和任务范围。只追问影响下一步的缺项，其余登记缺口。
3. 逐件读取实际资料并记录路径、类型、时间、适用范围、来源与 SHA256；未读取的材料不得声称已核验。
4. 区分用户已实现、正在实施、计划和估算。输出资料盘点、事实摘要和缺口，不能补造团队或成果。
5. 内置 `data/rubrics/NNN.json` 是历史规则线索。读取其 `provenance` 中每个字段的来源、状态与适用范围；旧 `official_wording` 字段名及历史 confidence 不代表已核验官方条款。未核验、范围不符、原文或字段已变的权重只能作为明确标注的参考，不能计算正式得分。项目检查返回 `ruleEvidence`；实际参赛仍须登记本届原文并由负责人逐项核对。

## 输出与验收
按照当前步骤 outputs 保存实际文件，登记来源和关键结果；用 ares_project 的 check 检查真实产物。
完成前提供内容复核 JSON，包含 summary、passed、findings 和 artifactHashes；hash 必须来自 check 结果。
复核必须实际阅读对应内容；仅机械检查通过不能宣称专业结论正确。失败修复后复测当前任务。
人工作业节点只能由团队提供原始记录并在工作台明确登记；模型不能替团队确认实测。
