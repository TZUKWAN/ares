# 演示文稿与视觉验收

适用：需要 PPTX 的步骤。输入来自当前步骤、项目事实、当届规则与前置实际产物。

## 执行要求
1. 按赛事、作品、受众和时长确定叙事与页大纲；数模、设计、工程、创业不能共用商业默认大纲。
2. 遵守用户的模板、工具和可编辑性要求，逐页设计。包内 build_ppt.py 仅是可选程序生成器，需提供真实 pages.json，不能把批量套版当作高质量完成。
3. 图片、图表、源文件和演示素材必须真实存在；没有产品原型的作品不强制Demo页或固定图片数量。
4. 内容数字绑定实际结果，页内按信息层级排布，检查字号、裁切、对齐、对比和可读性。
5. 独立打开/渲染PPTX并逐页检查；生成或XML解析通过只代表结构检查，不能声称已看过渲染效果。

## 与工作流衔接
- 当前会话有 ares_project / ares_library 时，先 status，再 open/read 当前步骤需要的能力。
- 按步骤 outputs 保存实际文件；check 后写真实内容复核记录，再 complete。失败记录原因并修复复测当前任务。
- 缺工具、数据、原文或人工结果时 block，不补造事实、不将计划当执行。
- 领域事实更新会使依赖结果需要复核。读取/安装技能不等于已经执行能力；本技能没有授予额外权限。
