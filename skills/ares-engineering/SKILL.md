# 工程与软件作品

适用：software / hardware。输入来自当前步骤、项目事实、当届规则与前置实际产物。

## 执行要求
1. 从命题形成可验收指标，明确工程环境、输入输出、精度、功耗、载荷或功能约束。
2. 软件按需求、架构、实际实现和行为测试推进；界面原型与可运行系统分别登记。
3. 机械、电路和控制按真实专业能力与工具完成设计、计算、仿真和源文件，不用泛化文字代替专业设计。
4. 仿真、样机、实测和计划四类状态分开。制作与现场测量是团队节点，模型不得认证实测。
5. 报告、BOM、操作说明、测试记录和演示由作品要求选择，不默认每项工程都是多页网页。

## 与工作流衔接
- 当前会话有 ares_project / ares_library 时，先 status，再 open/read 当前步骤需要的能力。
- 按步骤 outputs 保存实际文件；check 后写真实内容复核记录，再 complete。失败记录原因并修复复测当前任务。
- 缺工具、数据、原文或人工结果时 block，不补造事实、不将计划当执行。
- 领域事实更新会使依赖结果需要复核。读取/安装技能不等于已经执行能力；本技能没有授予额外权限。
