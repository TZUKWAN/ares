# ares-modeling L2 理科建模线

## 一、触发条件与输入

总控路由判定 pipeline 为 L2（数模/统计建模/理科实验创新）时调用。输入：赛题（题目原文或题号）、project.json（团队/语言偏好/目标奖项）、赛事 rubrics/NNN.json。

## 二、执行步骤（流程固化）

1. 赛题解析：识别问题类型（优化/评价/预测/机理/统计），列各问输入输出与约束。
2. 问题拆解与假设：逐问拆解；假设清单逐条标注合理性依据（论文模型假设节直接复用）。
3. 候选模型：每问给 2-3 个候选模型并说明选型理由（数据形态适配性/求解成本/结果可解释性）。
4. 代码实现与求解：Python（numpy/pandas/scipy/sklearn）或 MATLAB；脚本分模块（数据处理/模型/可视化），种子固定可复现。
5. 结果可视化：图表按 ares-data 风格（主题色、编号、来源）。
6. 论文成文：按默认结构组稿，排版走 ares-docx；正文遵守 ares-writing-style（建模论文允许数学符号与公式，不视为分点违规；但禁用词句纪律照常）。
7. 灵敏度/误差分析：关键参数 ±10%/±20% 扰动，结论稳定性论证。
8. 摘要精修：单独一轮。摘要决定生死：一页内覆盖 问题→模型→方法→主要结果数字→结论；数字必须与正文一致。

## 三、论文默认结构

摘要（独立成页）→ 问题重述 → 问题分析 → 模型假设 → 符号说明 → 模型建立与求解 → 结果分析 → 灵敏度分析 → 模型评价与推广 → 参考文献 → 附录（代码）。

## 四、美赛（id 83）特别规则

自动切换英文写作；MCM/ICM 官方格式：Summary Sheet 独立一页、Letter to the King 或按题要求、正文无中文；引用与图表英文规范；提交前提示 ZIP 命名与页数限制。

## 五、输入输出契约

- 输出：`输出/项目名/01-论文.docx`（摘要独立成页）、`02-求解代码/`、`03-实验数据/`、`04-结果图表/`；代码可运行并复现论文全部结果数字。
- 数据回填：结果关键数字（最优值/误差/排名）回填 project.json 后方可进论文。

## 五A、质检适配口径与题面渠道（建模线专项）

- 一致性扫描口径：论文关键结果数字（最优值/误差/终止时刻等）须先登记进 project.json 的 solution.performance_metrics（metric=指标名、value=数值），consistency_check 按"指标名同句 + 同单位数字"比对；未登记的数字不参与比对。
- 代码-论文一致性：论文中的结果数字直接取自代码输出的 JSON/表格，禁止手抄改写；交付前重跑 run_all 类入口一次做复现自检（xlsx 按单元格值比对而非字节）。
- 题面核实渠道：国赛真题从 mcm.edu.cn（全国组委会）下载原题；美赛从 comap.com。检索配额受限时直接抓取上述官网历年赛题页，不得仅凭用户转述设定数据（转述与官方冲突时以官方为准并写入假设节）。

## 六、质量自检清单

- [ ] 每问都有模型选型理由（2-3 候选对比）
- [ ] 代码重跑结果与论文数字一致（抽取 3 个关键数字核对）
- [ ] 摘要含主要结果数字且独立成页
- [ ] 灵敏度分析覆盖至少 2 个关键参数
- [ ] 图表编号/来源/主题色合规；参考文献 GB/T 7714（美赛按英文规范）
- [ ] 写作纪律机扫通过（--allow-questions 不适用于本线，正文不得有疑问句）

## 七、协作接口

调用：ares-writing-style、ares-docx、ares-data、ares-judge。训练备赛类需求（非真题）同样按本流程以历年真题为载体执行。
